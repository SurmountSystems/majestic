# Residual

## Operator residual

1. `just install` (runs `just check` first, then cargo install and strip to `~/.local/bin/memex`). `just check` is fmt, clippy, and nextest only; it does not install. Needs system `pcre2` (libpcre2; pacman `pcre2` or nix `pcre2`). Then `memex search 'lizard AND the'` (human AND, any order; compiles to PCRE2 lookaheads on one title or one message, not the whole archive). Regex form is `memex search '/(?=.*lizard)(?=.*the)/'`. If leftover `~/memex/**/*.archive` files are majestic v1 (magic `MAJESTIC` plus byte `0x01`), rename them to `.majestic`. Optional: `memex compress PATH.majestic` writes `PATH.majestic.zst` next to the file (zstd level 3, no dictionary) and keeps the uncompressed original. `memex decompress PATH.majestic.zst` writes `PATH.majestic` and keeps the `.zst`. Do not mmap `.zst`. Default ingest still writes uncompressed `.majestic`.
2. Remove pre-v1 archives under `$HOME/memex` (not source dumps). Ingest **fails** on old magic so you can trash those files yourself. Then `memex ingest` with no paths. Home scan now includes ChatGPT zips and unzipped `conversations-*.json` plus `user.json` (service `agents/chatgpt`, account `$USER`, never email). Meta `facebook-*.zip` / `instagram-*.zip` and unzipped `your_facebook_activity/` / `your_instagram_activity/` trees (service `social/meta`, account from `facebook-{account}-` or `instagram-{account}-` or `$USER`, never email; duplicate zip bytes in a group are skipped). X account archives (`twitter-*.zip` or unzipped `data/account.js` plus tweets; service `social/x`, account from `account.username`, never email; duplicate zip bytes in a group are skipped). Also Grok dumps, Telegram Desktop `result.json`, Obsidian vaults, `.agents/reports`, `session_search.sqlite` with `session_docs`. Zips are streamed from the central directory; they are not extracted. Does not ingest arbitrary markdown trees. Home scan skips system trash by default (XDG Trash, directory name `.Trash`, and names that start with `.Trash-`). Extra skips belong in `skip_directories` in `~/.config/majestic/memex.toml`. Crate defaults do not skip `~/.agents/trash`. The scan also skips `.git`, `node_modules`, `target`, `.cache`, `.cargo`, `.rustup`, `.npm`, `.nvm`, `Steam`, `.local/share/Steam`, `.local/share/TelegramDesktop`, `nix`, `proc`, and `$HOME/memex` as a source. Max 8 directory levels. No symlinks. Info logs path, inferred service/account, and skip reason. Never logs message bodies. Never print email or phone.
3. `just bench-zstd` on the current power-saver profile. Then switch to balanced and run it again. Then switch to performance and run it again. The recipe is niced 19 with idle ionice. It does not delete source archives or Downloads. Temps under `$HOME/memex/bench-zstd/` are `gio trash`'d after each level. JSONL plus markdown land there. Do not run a multi-hour 7.5G 44-level pass unless you mean to.
4. `memex search -i catfooding` with no service, account, or archive path. That searches every archive under `$HOME/memex`. A systemwide search lists paths, maps all listed archives and holds those maps, compiles PCRE2 once, clones the matcher per worker, then runs PCRE2 on each packed span of already-mapped text with `min(file count, available parallelism)` workers. Stderr shows `searching N archives` then `searching k/N path` and a running unique-hit count. `--format human` (default), `json`, or `toon` writes the report on stdout. It does not walk `$HOME` for live export dumps. Ingest owns discovery. Hits are unique (conversation id, field, entire packed span text). After uniqueness, identical packed bodies print once, then occurrence rows list archive path, conversation id, and field. Default print cap is 100 snippet groups (`--max-count`). `-i` is case insensitive. `-F` is a phrase or literal. `-w` is whole word. A pattern that is not slash-wrapped is a human query. `/regex/flags` is PCRE2. Search uses mmap text, grep-searcher, and grep-pcre2 only. There is no PCRE1 and no rust-regex fallback. AND any order: `memex search 'lizard AND the'`. Both words must sit in the same title or the same message, not anywhere in the archive. Open maps each `.majestic` with `PROT_READ` and `MAP_SHARED`. That is a virtual map, not a heap allocation. RSS is pages PCRE2 faulted, not the file size at `mmap()`. New ingest starts the UTF-8 text on a 2 MiB file offset. `MADV_COLLAPSE` failure is DEBUG and does not abort open.

   | Want | Pattern |
   | --- | --- |
   | OR | `lizard OR catfooding` or `lizard\|catfooding` |
   | AND, any order | `lizard AND the` |
   | Phrase | `"hello world"` or `-F 'hello world'` |
   | Case insensitive | `-i` or `/Catfooding/i` |
   | Whole word | `-w` |
   | Regex | `/<regex>/` flags: `i`, `g`, `m`, `s`, `x` |

## Agent residual

1. `just check` (fmt, clippy, nextest). Agents did not run cargo. Then `just install` so `~/.local/bin/memex` maps each `.majestic` with `PROT_READ` and `MAP_SHARED` at a 2 MiB-aligned virtual address, pads new ingest so text starts at a 2 MiB file offset, calls `MADV_HUGEPAGE` then `MADV_COLLAPSE` on the text (collapse errors are DEBUG; open still succeeds), holds every listed map, compiles PCRE2 once, clones the matcher per worker, and searches each packed span of already-mapped text with `min(file count, available parallelism)` workers. Stderr shows `searching N archives` then `searching k/N path` and a running unique-hit count. `--format human` (default), `json`, or `toon` writes the report on stdout. Human queries (`lizard AND the`, `lizard OR catfooding`, `"hello world"`) compile in `src/query.rs`. AND requires both words in the same title or the same message. Unique hits key on conversation id, field, and the entire packed span text, not the snippet window and not the packed start offset. One packed message is one hit. Duplicate packed copies of the same body stay one hit. After uniqueness, identical packed bodies print once with occurrence rows (archive path, conversation id, field). The default print cap of 100 snippet groups stays.
